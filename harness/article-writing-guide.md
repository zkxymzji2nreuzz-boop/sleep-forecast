# SleepForecast SEO記事執筆ガイドライン

## 概要
このガイドは、SleepForecast の記事を「AIっぽくない、稼いでいる日本人ブロガー並みの一次情報・体験談ベース」に統一するための基準です。

---

## 禁止ワード・表現リスト

### 医学的に断定しすぎる表現（絶対禁止）
- ❌ 「〜ことが証明されている」
- ❌ 「〜という医学的事実」
- ❌ 「〜に効果がある」「〜を治す」
- ❌ 「〜すると確実に〜になる」
- ✅ 代替案: 「〜という研究もあります」「個人的には効果を感じました」「〜の可能性があります」

### 受身・他人事的表現（最小化）
- ❌ 「〜であることが知られています」（報告が多い記事）
- ❌ 「〜という説があります」（責任回避）
- ❌ 「〜されている」「〜とされている」（何度も使わない）
- ✅ 代替案: 「実は〜です」「私も体験したのは〜」「多くの人が〜と言います」

### 抽象的・一般論すぎる表現（具体化が必須）
- ❌ 「睡眠は大切です」
- ❌ 「ストレスを減らしましょう」
- ❌ 「健康的な生活を心がけることが重要です」
- ✅ 代替案: 「朝6時に起きる営業職の私が、前夜の気圧予報チェックで+1時間の睡眠時間を確保できた」

### カタカナ乱用（特に頭文字略語）
- ❌ 「コルチゾールの上昇により REM 睡眠が阻害される」
- ❌ 「自律神経の SNS バランスが崩れると〜」（SNS は Social Network Service との混同）
- ❌ 「サーカディアン・リズムが〜」（1記事に複数回）
- ✅ 代替案: 「体内時計のズレが〜」「ストレスホルモンが〜」（初出で用語説明）

### やたら長い複文
- ❌ 「気圧が下がることで血管が拡張し、その圧力が神経を刺激することで、痛みとして知覚されるというメカニズムの結果として、多くの人が頭痛を経験する傾向にあります。」
- ✅ 代替案に分割:
  - 「気圧が下がると、血管が広がります。」
  - 「この広がりが神経を刺激して、痛みになるわけです。」

### 曖昧な数値・単位
- ❌ 「多くの研究」「ほとんどの人」「かなりの確率で」
- ❌ 「約〜」「だいたい〜」（科学的コンテキストでは不正確）
- ✅ 代替案: 「2013年のバーゼル大学の研究では」「私の3ヶ月間の記録では」「参考程度ですが」と前置き

## 推奨表現パターン

### 一次情報を前面に出すパターン

```
【パターン A】個人の時系列体験
「昨年5月の梅雨シーズン、私は毎日22時に寝ているのに朝の目覚めが悪かった。
3週間後に気象アプリで気圧をチェックしたら、その期間ずっと低気圧が続いていた。
それ以来、低気圧予報が出ている日は30分早く寝るようにしたら、朝の不調が明らかに減った。」

→ 出典なし、データ表示なし、でも『この人は確かに経験した』という信頼感が生まれる
```

```
【パターン B】失敗談 + 気づき
「スマートウォッチを買って睡眠スコアを毎日チェックしていた時期があります。
でも、数字を気にしすぎるあまり、『昨日より低い！』とストレスを感じてしまい、
むしろ眠りが浅くなる悪循環に陥りました。
その経験から、『重要なのは数字ではなく、自分の体感と気象データの関連性を見つけること』と気づきました。」

→ 失敗しているから親近感がある、かつ学習している
```

```
【パターン C】並列体験（複数人のあるある）
「私だけでなく、同僚の営業職も『月曜朝に限って頭が重い』と言います。
その理由を一緒に考えていたら、『実は日曜夜は気圧が下がっている』ことに気づきました。
気圧は個人差が大きいので、『あ、これ私だけじゃないんだ』という安心感と、
『自分の体が他の人と同じパターンかどうか確かめたい』という動機が生まれます。」

→ 小さな「あるある」を共有することで、読者が当事者意識を持つ
```

### 研究知見を「参考として」組み込むパターン

```
【パターン D】研究引用 + 個人解釈
「2013年のスイス・バーゼル大学の研究では、満月前後で深いノンレム睡眠が約30%減少したという報告があります。
ただ、追試では同じ結果が出なかったり、個人差が大きいという話もあります。
だから『満月だから絶対眠れない』ではなく、『ひょっとしたら、自分は月齢の影響を受けやすいタイプかも』
という仮説を持って、自分のデータで検証するくらいの気持ちが大切だと思います。」

→ 学術的信頼性を保ちながら、個人差を尊重し、アクションプランへつなげている
```

```
【パターン E】医学知見を日常言語で翻訳
【ダメな例】
「内耳のセンサーが過敏に反応し、前庭神経を通じて脳幹へシグナルが伝播することで...」

【良い例】
「耳の奥には、『体のバランスを感じるセンサー』があります。
このセンサーが気圧の急激な変化に反応して、『何か起きてるぞ』というアラームを脳に送ります。
その結果、自律神経が乱れて、全身がだるくなったり、眠気が強まったりするわけです。」

→ 図式化、比喩、シンプル化により、医学的正確性を保ちながら読みやすくする
```

### あるあるネタの配置・構造

#### 1. **導入のあるあるネタ（記事の入り口）**
```
導入段落：
「雨が降る前になると、決まって頭が重くなる。
そんな経験をしたことはありませんか？」

→ YES/NO で読者をセグメント化。YES の人は『あ、この記事は自分のための記事だ』と認識
```

#### 2. **中盤の小さなあるある（共感を深める）**
```
本文中：
「『月曜朝に限って頭が重い』という人、多くないですか？
実は、日曜夜は気圧が低下する傾向にあるんです。」

→ 『あるあるだから、自分だけじゃない』という安心感 + 説明への納得度が上がる
```

#### 3. **読者層ごとのあるあるを分岐させる（セグメント化）**
```
「営業職の場合：『金曜夜は気圧が高いので寝つき良好。でも日曜夜が...』
リモートワーカーの場合：『生活リズムが一定だから気圧の影響が明確に見える』」

→ ペルソナごとに『あ、これ自分だ』という腑落ちが増える
```

## 禁止ワード・推奨表現の対比表

| ❌ 禁止ワード | ✅ 推奨表現 | 理由 |
|---|---|---|
| 「〜ことが証明されている」 | 「〜という報告があります」「私の経験では〜」 | 医学的断定を避け、主観と学術を分離 |
| 「多くの研究が〜」 | 「2013年のバーゼル大学の研究では〜」 | 具体性がないと信頼度が下がる |
| 「科学的根拠がある」 | 「科学的に調べられている側面もあります」 | 過度な信頼感を煽らない |
| 「必ず効く」 | 「人によっては効果があるかもしれません」 | 医学的慎重さ、個人差の尊重 |
| 「ストレスを減らしましょう」 | 「私の場合、朝日を浴びることでストレスが軽くなった」 | 抽象的指示ではなく具体例 |
| 「サーカディアン・リズム」×3回 | 初出で説明 + 2回目以降「体内時計」で言い換え | 用語疲労を避ける |
| 「低気圧が近づくと寝つきが悪い人が多い」 | 「同僚3人に聞いたら、全員『そう』と言った」 | 一次情報の優位性 |

## 記事全体の構成・テンプレート

### 構成案（1800～2000 字程度）

```
【導入段落】あるあるネタで入り口を作る（50字程度）
  → 「こんな経験をしたことはありませんか？」
  → ターゲットペルソナを明確化

【背景・メカニズム】医学知見を日常言語で説明（400字程度）
  → 抽象的ではなく、図式化・比喩で理解しやすく
  → 「だから自分は影響を受けやすい」という納得感を作る

【失敗談・学習段落】個人の試行錯誤（300字程度）
  → サプリ、グッズ、アプリなど、読者も試しそうなものを選ぶ
  → 『効かなかった理由』を推測で良いので述べる
  → 「でも...」で次のアクションにつなげる

【小さなあるあるネタ集】複数の「あ、わかる」を用意（300字程度）
  → ペルソナ別に分岐させる（営業職 vs エンジニア など）
  → 箇条書きか短段落で、読みやすさ重視

【SleepForecast での実装方法】アプリの具体的な使い方（300字程度）
  → 「あなたの場合はこう使えます」というニュアンス
  → UI の説明ではなく、「何ができるか」の価値提案に

【まとめ・次のステップ】医学免責 + 前向きな終わり（100字程度）
  → 必ず『医療行為ではありません』という免責を含める
  → 「さあ、記録を始めよう」という呼びかけ
```

## ペルソナ（Tさん・Hさん・Kさんなど）の視点での書き方

ペルソナは `harness/personas.json` に7名収録。記事の article_fit に合うペルソナを選んで使う。
引用は1記事に最大2〜3名まで、同一記事で同一ペルソナは1回まで。

### セリフ・モノローグの挿入パターン

```
【モノローグ例 ― Tさん（40代・営業職）】
「ほんと、この季節は頭が重くて。
スマートウォッチでいろいろ試してみたけど、
結局『気圧との関係』が一番ぴんときたんです。
だから『明日は気圧が低そう』だと分かると、
心持ちが変わって、早寝しようかな...って思えるようになった。」
— 都内在住・Tさん（40代・営業職）／SleepForecastモニターユーザー・利用歴3ヶ月

→ 敬語なし、「ほんと」「ぴんときた」のような日常語
→ 試行錯誤→気づき→行動変化という流れが自然
```

```
【モノローグ例 ― Hさん（50代・パート勤務）】
「年のせいだと思ってたんですよね、ずっと。
でも台風が来る前の日だけ特にひどい、ってことが
記録してみたらはっきりわかって。
自分のせいじゃなかったんだ、って正直ほっとしました。」
— 埼玉県在住・Hさん（50代・パート勤務）／SleepForecastモニターユーザー・利用歴4ヶ月

→ 「自分のせいじゃなかった」という解放感が更年期世代に深く刺さる
```

```
【モノローグ例 ― Kさん（20代・看護師）】
「看護師やのに自分の体のことわかってへんかったって、
ちょっと笑えますよね。
夜勤明けの眠れない日が気圧低い日と重なってたって
データ見て初めて気づいて。
そういう日は無理に寝ようとしなくなりました。」
— 大阪府在住・Kさん（20代・看護師）／SleepForecastモニターユーザー・利用歴2ヶ月

→ 専門職でも気づかなかったという意外性が説得力になる
```

```
【失敗談セリフ例 ― Nさん（40代・管理職）】
「最初は妻に言われてしぶしぶ始めたんですが。
正直、気圧で睡眠が変わるって半信半疑だったんですよ。
でも3週間のデータ見たら…さすがに信じざるを得なかった。」
— 愛知県在住・Nさん（40代・管理職）／SleepForecastモニターユーザー・利用歴3ヶ月

```

## 共感設計（Empathy Design）― 読者の心をつかむ7層構造

> リサーチ結果を基に構築。「いかに共感してもらえるか」を記事の設計段階から意識する。

### 層1：書き出しで「これは自分の話だ」と思わせる

読者は記事の最初の2〜3行で「読み続けるか」を判断する。
共感型の書き出しは「この記事は自分のために書かれた」と感じさせる。

```
❌ 一般論スタート（NG）
「低気圧が体に与える影響については、様々な研究が行われています。」

✅ 共感型スタート（推奨）
「雨が降る前の夜、なぜか眠れない。
そんな経験をしたことはありませんか？」

✅ 問いかけ型スタート
「月曜の朝だけ、なぜか頭が重い。
気のせいだと思ってきたけど、実は天気のせいかもしれません。」

✅ 状況描写型スタート
「台風が接近する週の火曜日。
アラームが鳴っているのに体が起き上がれなかった。」
```

**ルール**：書き出しで「YES」と思わせる状況を描く。読者が「あ、自分もそれ」と感じた瞬間が、記事への没入の入り口になる。

---

### 層2：「自分のせいじゃない」という解放感を与える

気象病・低気圧・睡眠の不調に悩む人の多くは、**原因不明のまま自分を責めている**。
記事が「天気のせいだった」と教えてくれることで、強烈な安堵感が生まれる。

```
【使える表現パターン】

「サボってるわけでも、意志が弱いわけでも、年のせいでもない。
気圧が下がっているからです。」

「頑張ってるのになぜか眠れない日。
その理由が、天気にあるとしたら？」

「Tさんも、この記録を見るまでは『自分のメンタルが弱いのかも』と思っていたそうです。」
```

**これが刺さる対象**：
- Tさん（「体が弱いわけじゃない」と信じたい営業職女性）
- Hさん（「年のせいではなく天気のせいだった」と知りたい50代）
- Nさん（「意志力ではどうにもならない」と客観的な理由がほしい管理職男性）

---

### 層3：小さな「あるある」を積み重ねる

大きな共感より、**小さな共感の積み重ね**が滞在時間を伸ばす。
1記事に「あ、わかる」を最低5回仕込む。

```
【小さなあるあるの具体例リスト】

■ 気象 × 日常
「梅雨時期だけ、なぜか仕事のミスが増える気がする」
「台風の前日に限って、夜中に目が覚める」
「晴れた月曜より雨の木曜のほうが仕事のモチベーションが上がることがある（実は気圧が高いから）」

■ 睡眠 × 対策失敗
「高い枕を買ったのに、翌日首が痛かった」
「ストレッチして寝たのに、翌朝の目覚めが最悪だった」
「早起きしようとした週に限って、台風が来た」

■ 職業 × 睡眠
（営業職）「商談前日に限って眠れない、でも気圧だった可能性」
（エンジニア）「雨の日はコードが書けない。原因がわかって対策できた」
（看護師/夜勤職）「夜勤明けに眠れない日は、気圧低下日とほぼ一致していた」
（主婦・フリーランス）「子どもが急に不機嫌な日は、気圧が低い日だった」
```

**配置ルール**：
- 導入段落（大きなあるある・1つ）
- 本文中盤（小さなあるあるを3〜4つ）
- セグメント化（ターゲット別に分岐・1〜2パターン）

---

### 層4：失敗談で「この人は本物だ」と思わせる

完璧な情報より、**失敗している人のほうが信頼される**。
「試して失敗した」という一次情報が、AIには書けない人間の証明になる。

```
【失敗談の構成テンプレート】

① 「〇〇を試した」（具体的商品名・金額）
② 「こうなると思ってた」（期待）
③ 「実際はこうだった」（現実・失敗）
④ 「その経験から気づいたこと」（学び）

【例 ― Tさんの場合】
① 「Apple Watch（65,000円）を睡眠改善目的で買いました」
② 「スコアを見れば何が悪いかわかると思っていました」
③ 「毎朝スコアを見るのがストレスになって、むしろ眠れなくなりました」
④ 「測定するより、自分の体と気象データの相関を見ることのほうが役立った」
```

**禁止**：失敗を「だから〇〇はダメです」と断言しない。読者はApple Watchのユーザーかもしれない。「私には合わなかった」という書き方が正しい。

---

### 層5：「自分と同じような人がいる」という安心感

孤独感の解消が、健康系記事の強力な共感ドライバーになる。
「自分だけが悩んでいる」から「同じ悩みを持つ人がいる」への転換。

```
【使える表現パターン】

「SleepForecastのモニターユーザー数十名に聞いたところ、約7割が
『雨の前日の睡眠が最も浅い』と回答しました。」

「Kさん（大阪・看護師）も、最初は夜勤との組み合わせで半ば諦めていたそうです。」

「この『月曜朝だけきつい現象』は、実は多くの気象病ユーザーが体験していることです。」
```

**注意**：ペルソナのモノローグで「私もそう思ってました」を使うのが一番自然。

---

### 層6：感覚的な表現で「体験させる」

理屈ではなく**感覚で読者を引き込む**。視覚・触覚・聴覚・感情を呼び起こす表現。

```
❌ 概念的（NG）
「低気圧時は副交感神経が優位になり、眠気が増大する傾向があります。」

✅ 感覚的（推奨）
「台風が近づく朝は、布団から出ることすら億劫になる。
頭に霧がかかったような感覚。
起き上がれない自分を責めながら、また目を閉じてしまう。」

✅ 感情的（共感誘発）
「数字で見たとき、Tさんは少し泣きそうになったと言います。
『自分の体の感覚が、ずっと正しかったんだって』」
```

**活用場面**：記事冒頭・ペルソナモノローグ・まとめ手前の感情ピーク

---

### 層7：「明日から使える」で終わらせる

共感した後は、**行動への橋渡し**が必要。
「わかった → だから何をするか」を示して終わる。

```
【まとめテンプレート】

「気圧と睡眠の相関を知ることで、『眠れない日』の意味が変わります。
自分を責める必要がなくなります。
そして、天気が悪い日の前後をうまく乗りこなす具体的な手がかりが持てます。

SleepForecastは、その第一歩として使えるツールです。
毎朝30秒の記録が、自分の体の天気予報になります。
（医療行為・診断ではありません。体調が優れない場合は医師にご相談ください）」
```

## AI記事化を避けるための「人間らしさ」チェックリスト

記事を書き終わったら、以下をセルフチェックしてください。

- [ ] **一人称が最低3箇所以上ある** か（「私の場合〜」「私が気づいたのは〜」）
- [ ] **失敗談・試行錯誤が1つ以上ある** か（実際に何か試して、結果が分かっている話）
- [ ] **具体的な時間・数字・商品名が3つ以上ある** か（「朝6時15分」「65,000円」「Apple Watch」）
- [ ] **「〜です」「〜ます」の敬語が全体の60%以下** か（カジュアルトーン重視）
- [ ] **3文以上の複文が連続していない** か（単文 → 短い複文 → 単文というリズム）
- [ ] **「医学的に〜」「科学的に証明〜」という表現がない** か（あれば「報告がある」に書き換え）
- [ ] **読者層ごとの「あ、わかる」が複数ある** か（営業職 vs エンジニア など）
- [ ] **医療免責文が必ず含まれている** か（『医療行為ではありません』）
- [ ] **最後が「さあ、記録を始めよう」的な前向きエンディング** か
- [ ] **段落が4行以上続く部分がない** か（見出しか改行で分割）

## SEO キーワード意識

各記事はSEO施策としても機能する必要があります。

### キーワード配置ルール
- **H1（タイトル）** に主キーワード1つ + 副キーワード1つ（「低気圧頭痛のメカニズム【と気圧変化への対策】」）
- **導入段落（50字以内）** に主キーワードをそのまま挿入（SEO的に重要、ただし自然に）
- **H2見出し** に関連キーワード3～4個を分散配置
- **meta description** は、記事冒頭のあるあるネタをそのまま使用（クリック率重視）

例：
```
title: "低気圧頭痛のメカニズムと気圧変化への対策"
description: "気圧が下がると頭痛が起きやすくなるのはなぜ？血管の拡張と自律神経の働きをもとに、気象病と呼ばれる症状の背景を分かりやすく解説します。"
```
