# SleepForecast SEO記事執筆ガイドライン

## 概要
このガイドは、SleepForecast の記事を「AIっぽくない、稼いでいる日本人ブロガー並みの一次情報・体験談ベース」に統一するための基準です。

## 禁止ワード・表現リスト

### 医学的に断定しすぎる表現（絶対禁止）
- ❌ 「〜ことが証明されている」
- ❌ 「〜という医学的事実」
- ❌ 「〜に効果がある」「〜を治す」
- ❌ 「〜すると確実に〜になる」
- ✅ 代替案: 「〜という研究もあります」「個人的には効果を感じました」「〜の可能性があります」

### 受身・他人事的表現（最小化）
- ❌ 「〜であることが知られています」（報告が多い記事）
- ❌ 「〜という説があります」（責任回避）
- ❌ 「〜されている」「〜とされている」（何度も使わない）
- ✅ 代替案: 「実は〜です」「私も体験したのは〜」「多くの人が〜と言います」

### 抽象的・一般論すぎる表現（具体化が必須）
- ❌ 「睡眠は大切です」
- ❌ 「ストレスを減らしましょう」
- ❌ 「健康的な生活を心がけることが重要です」
- ✅ 代替案: 「朝6時に起きる営業職の私が、前夜の気圧予報チェックで+1時間の睡眠時間を確保できた」

### カタカナ乱用（特に頭文字略語）
- ❌ 「コルチゾールの上昇により REM 睡眠が阻害される」
- ❌ 「自律神経の SNS バランスが崩れると〜」（SNS は Social Network Service との混同）
- ❌ 「サーカディアン・リズムが〜」（1記事に複数回）
- ✅ 代替案: 「体内時計のズレが〜」「ストレスホルモンが〜」（初出で用語説明）

### やたら長い複文
- ❌ 「気圧が下がることで血管が拡張し、その圧力が神経を刺激することで、痛みとして知覚されるというメカニズムの結果として、多くの人が頭痛を経験する傾向にあります。」
- ✅ 代替案に分割:
  - 「気圧が下がると、血管が広がります。」
  - 「この広がりが神経を刺激して、痛みになるわけです。」

### 曖昧な数値・単位
- ❌ 「多くの研究」「ほとんどの人」「かなりの確率で」
- ❌ 「約〜」「だいたい〜」（科学的コンテキストでは不正確）
- ✅ 代替案: 「2013年のバーゼル大学の研究では」「私の3ヶ月間の記録では」「参考程度ですが」と前置き

## 推奨表現パターン

### 一次情報を前面に出すパターン

```
【パターン A】個人の時系列体験
「昨年5月の梅雨シーズン、私は毎日22時に寝ているのに朝の目覚めが悪かった。
3週間後に気象アプリで気圧をチェックしたら、その期間ずっと低気圧が続いていた。
それ以来、低気圧予報が出ている日は30分早く寝るようにしたら、朝の不調が明らかに減った。」

→ 出典なし、データ表示なし、でも『この人は確かに経験した』という信頼感が生まれる
```

```
【パターン B】失敗談 + 気づき
「スマートウォッチを買って睡眠スコアを毎日チェックしていた時期があります。
でも、数字を気にしすぎるあまり、『昨日より低い！』とストレスを感じてしまい、
むしろ眠りが浅くなる悪循環に陥りました。
その経験から、『重要なのは数字ではなく、自分の体感と気象データの関連性を見つけること』と気づきました。」

→ 失敗しているから親近感がある、かつ学習している
```

```
【パターン C】並列体験（複数人のあるある）
「私だけでなく、同僚の営業職も『月曜朝に限って頭が重い』と言います。
その理由を一緒に考えていたら、『実は日曜夜は気圧が下がっている』ことに気づきました。
気圧は個人差が大きいので、『あ、これ私だけじゃないんだ』という安心感と、
『自分の体が他の人と同じパターンかどうか確かめたい』という動機が生まれます。」

→ 小さな「あるある」を共有することで、読者が当事者意識を持つ
```

### 研究知見を「参考として」組み込むパターン

```
【パターン D】研究引用 + 個人解釈
「2013年のスイス・バーゼル大学の研究では、満月前後で深いノンレム睡眠が約30%減少したという報告があります。
ただ、追試では同じ結果が出なかったり、個人差が大きいという話もあります。
だから『満月だから絶対眠れない』ではなく、『ひょっとしたら、自分は月齢の影響を受けやすいタイプかも』
という仮説を持って、自分のデータで検証するくらいの気持ちが大切だと思います。」

→ 学術的信頼性を保ちながら、個人差を尊重し、アクションプランへつなげている
```

```
【パターン E】医学知見を日常言語で翻訳
【ダメな例】
「内耳のセンサーが過敏に反応し、前庭神経を通じて脳幹へシグナルが伝播することで...」

【良い例】
「耳の奥には、『体のバランスを感じるセンサー』があります。
このセンサーが気圧の急激な変化に反応して、『何か起きてるぞ』というアラームを脳に送ります。
その結果、自律神経が乱れて、全身がだるくなったり、眠気が強まったりするわけです。」

→ 図式化、比喩、シンプル化により、医学的正確性を保ちながら読みやすくする
```

### あるあるネタの配置・構造

#### 1. **導入のあるあるネタ（記事の入り口）**
```
導入段落：
「雨が降る前になると、決まって頭が重くなる。
そんな経験をしたことはありませんか？」

→ YES/NO で読者をセグメント化。YES の人は『あ、この記事は自分のための記事だ』と認識
```

#### 2. **中盤の小さなあるある（共感を深める）**
```
本文中：
「『月曜朝に限って頭が重い』という人、多くないですか？
実は、日曜夜は気圧が低下する傾向にあるんです。」

→ 『あるあるだから、自分だけじゃない』という安心感 + 説明への納得度が上がる
```

#### 3. **読者層ごとのあるあるを分岐させる（セグメント化）**
```
「営業職の場合：『金曜夜は気圧が高いので寝つき良好。でも日曜夜が...』
リモートワーカーの場合：『生活リズムが一定だから気圧の影響が明確に見える』」

→ ペルソナごとに『あ、これ自分だ』という腑落ちが増える
```

## 禁止ワード・推奨表現の対比表

| ❌ 禁止ワード | ✅ 推奨表現 | 理由 |
|---|---|---|
| 「〜ことが証明されている」 | 「〜という報告があります」「私の経験では〜」 | 医学的断定を避け、主観と学術を分離 |
| 「多くの研究が〜」 | 「2013年のバーゼル大学の研究では〜」 | 具体性がないと信頼度が下がる |
| 「科学的根拠がある」 | 「科学的に調べられている側面もあります」 | 過度な信頼感を煽らない |
| 「必ず効く」 | 「人によっては効果があるかもしれません」 | 医学的慎重さ、個人差の尊重 |
| 「ストレスを減らしましょう」 | 「私の場合、朝日を浴びることでストレスが軽くなった」 | 抽象的指示ではなく具体例 |
| 「サーカディアン・リズム」×3回 | 初出で説明 + 2回目以降「体内時計」で言い換え | 用語疲労を避ける |
| 「低気圧が近づくと寝つきが悪い人が多い」 | 「同僚3人に聞いたら、全員『そう』と言った」 | 一次情報の優位性 |

## 記事全体の構成・テンプレート

### 構成案（1800～2000 字程度）

```
【導入段落】あるあるネタで入り口を作る（50字程度）
  → 「こんな経験をしたことはありませんか？」
  → ターゲットペルソナを明確化

【背景・メカニズム】医学知見を日常言語で説明（400字程度）
  → 抽象的ではなく、図式化・比喩で理解しやすく
  → 「だから自分は影響を受けやすい」という納得感を作る

【失敗談・学習段落】個人の試行錯誤（300字程度）
  → サプリ、グッズ、アプリなど、読者も試しそうなものを選ぶ
  → 『効かなかった理由』を推測で良いので述べる
  → 「でも...」で次のアクションにつなげる

【小さなあるあるネタ集】複数の「あ、わかる」を用意（300字程度）
  → ペルソナ別に分岐させる（営業職 vs エンジニア など）
  → 箇条書きか短段落で、読みやすさ重視

【SleepForecast での実装方法】アプリの具体的な使い方（300字程度）
  → 「あなたの場合はこう使えます」というニュアンス
  → UI の説明ではなく、「何ができるか」の価値提案に

【まとめ・次のステップ】医学免責 + 前向きな終わり（100字程度）
  → 必ず『医療行為ではありません』という免責を含める
  → 「さあ、記録を始めよう」という呼びかけ
```

## ペルソナ「田中由紀恵さん」の視点での書き方

### セリフ・モノローグの挿入パターン

田中さん（42歳、マーケ営業）の声で書き込むことで、読者の共感度が格段に上がります。

```
【モノローグ例】
「ほんと、この季節は頭が重くて。
スマートウォッチでいろいろ試してみたけど、
結局『気圧との関係』が一番ぴんときたんです。
だから『明日は気圧が低そう』だと分かると、
心持ちが変わって、早寝しようかな...って思えるようになった。」

→ 敬語なし、「ほんと」「ぴんときた」のような日常語、
→ 試行錯誤→気づき→行動変化という流れが自然
```

```
【セリフ例】
「同僚から『月曜朝、いつも頭重いんですよ』と聞いて、
『あ、それ、気圧かもしれませんよ』って返したんです。
そしたら『えっ、そんなことが関係あるんですか？』と驚かれて...」

→ 読者同士の『気づきの共有』を疑似体験させる
→ 記者が『専門家』ではなく『同じ悩みを持つ人』に見える
```

```
【失敗談セリフ例】
「GABA サプリ、毎月 3,000 円で 3 ヶ月飲んでました。
『科学的根拠あり』って書いてあったから期待したんだけど...
正直なところ、プラシーボなのか何なのか、判断がつかなくて。」

→ 「だから失敗した」と責める感じではなく、
→ 「わからない」という正直さが信頼を呼ぶ
```

## AI記事化を避けるための「人間らしさ」チェックリスト

記事を書き終わったら、以下をセルフチェックしてください。

- [ ] **一人称が最低3箇所以上ある** か（「私の場合〜」「私が気づいたのは〜」）
- [ ] **失敗談・試行錯誤が1つ以上ある** か（実際に何か試して、結果が分かっている話）
- [ ] **具体的な時間・数字・商品名が3つ以上ある** か（「朝6時15分」「65,000円」「Apple Watch」）
- [ ] **「〜です」「〜ます」の敬語が全体の60%以下** か（カジュアルトーン重視）
- [ ] **3文以上の複文が連続していない** か（単文 → 短い複文 → 単文というリズム）
- [ ] **「医学的に〜」「科学的に証明〜」という表現がない** か（あれば「報告がある」に書き換え）
- [ ] **読者層ごとの「あ、わかる」が複数ある** か（営業職 vs エンジニア など）
- [ ] **医療免責文が必ず含まれている** か（『医療行為ではありません』）
- [ ] **最後が「さあ、記録を始めよう」的な前向きエンディング** か
- [ ] **段落が4行以上続く部分がない** か（見出しか改行で分割）

## SEO キーワード意識

各記事はSEO施策としても機能する必要があります。

### キーワード配置ルール
- **H1（タイトル）** に主キーワード1つ + 副キーワード1つ（「低気圧頭痛のメカニズム【と気圧変化への対策】」）
- **導入段落（50字以内）** に主キーワードをそのまま挿入（SEO的に重要、ただし自然に）
- **H2見出し** に関連キーワード3～4個を分散配置
- **meta description** は、記事冒頭のあるあるネタをそのまま使用（クリック率重視）

例：
```
title: "低気圧頭痛のメカニズムと気圧変化への対策"
description: "気圧が下がると頭痛が起きやすくなるのはなぜ？血管の拡張と自律神経の働きをもとに、気象病と呼ばれる症状の背景を分かりやすく解説します。"
```

- [元作家が教えるAI文章の稼げる使い方](https://note.com/kuronekoyagogo/n/n2b3730bf03ad) — クロネコ屋
- [月収100万円の副業ブロガーが分析した「儲かる記事の共通点」](https://the21.php.co.jp/detail/9635) — THE21
- [人気/有名ブロガーを徹底分析](https://heysho.com/en/japanese-popular-bloggers/) — HeyShow

共通点：
1. **一次情報を最優先** — 「自分が実際に試した」という情報密度が高い
2. **失敗談を躊躇わない** — 完璧な情報より「試行錯誤の跡」が信頼を呼ぶ
3. **読者の小さな共感を大切にする** — 「あ、わかる」の積み重ねが滞在時間を伸ばす
4. **医学的断定を避ける** — 根拠のない言い切りより「個人的には」が信頼度を上げる

これらを SleepForecast の記事に組み込むことで、アクセス数・滞在時間・SNS シェア率の向上が期待できます。
